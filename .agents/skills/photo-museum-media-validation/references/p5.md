# P5 四展厅复验

先读 `docs/decisions/0005-p5-exhibition-rooms.md` 与 `docs/research/p5-exhibition-validation.md`。首次Gallery仍为Cover Flow；新增展厅不能替换它。地图底图在本地，不能引入第三方瓦片来完成测试。

为避免在验证期间把新界面送到正式服务，先隔离构建：

```bash
npm run build --prefix web -- --outDir ../data/p5-validation/web-dist --emptyOutDir
PYTHONPATH=. uv run --all-extras python tools/p5_validation_server.py
```

该fixture监听8795，准备84张合成图及显式元数据；等 `P5 synthetic ready` 和HTTP可用后再运行：

```bash
uv run --all-extras pytest -q tests/p1/test_exhibitions.py
node web/tests/p5.mjs
node web/tests/p5-states.mjs
```

两个浏览器脚本使用独立context和fixture密码，不读正式凭据。公开截图只含合成图；失败截图在忽略的data。`p5.mjs`覆盖日期/地点/器材到照片墙和暗房的往返、会话恢复、资源释放、短桌面/手机、减少动态效果、底图故障与零外部请求；`p5-states.mjs`注入空数据并检查键盘菜单。不能将注入元数据或空响应当真实照片/实际库状态。

注意年度照片不伪造月日，未接受推断不参与日历/GPS；人工null优先，GPS输入记录变更使旧地址不可用。中文地址保留最近城市精度。器材图是结构或类型示意，不是精确CAD。器材五图不能产生隐式新行挤压主图。仅缩略图/4K参与展厅预热；访问单图前不得出现original请求。

共享Gallery/PhotoWall发生变化时复验原CoverFlow。以隔离构建启动8794 fixture，准备需数分钟；ready后可设置以下环境变量，避免覆盖历史报告：

```bash
MUSEUM_BROWSER_OUTPUT=docs/design/previews/p5/coverflow-regression \
MUSEUM_BROWSER_EVIDENCE=docs/research/p5-coverflow-evidence.json \
node web/tests/coverflow.mjs
```

正式切换前完成全量Python回归与生产构建；正常退出原supervisor再启动相同数据目录，不改变源/队列/模型版本。确认API与五类进程（启用模型时）存活、原任务继续。未登录的P5接口应401；真实目录/GPS/照片证据只写data。结束时停止自己的8794/8795 fixture，保留8790及用户Gallery页；真实用户密码仍由用户输入。
