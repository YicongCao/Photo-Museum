2026-10-26。单图底栏采用实际字节驱动的进度，替代原图读取时的无进度圆环。其他缓存读取场景继续复用 PhotoLoading。

馆主要求先生成概念再实现。Imagegen 产出保存在 [原图进度概念](../design/concepts/original-progress-instrument.png)，使用生成山景，不上传私密照片。仅采纳底栏：概念中的其他按钮、坐标、RAW 示例和 EXIF 均不属于产品变更。

- 160 根圆角细刻度，未完成为深炭灰；已完成从古铜到香槟金，前沿一根稍亮、只有极窄光晕。以 SVG/CSS 实现，没有把概念位图贴入界面。
- 上行：已有下载线条图标、当前阶段、接收字节与更清晰的百分比；下行为横贯底栏的刻度。右侧铺满按钮使用细线对角箭头。
- 固定 56px 底栏，桌面/手机分别留 28/16px 边距。照片区域的宽高比计算相应调整；进度消失不改变底栏高度，不让照片跳动。
- 原图完成解码后目标才到 100%。百分比直接显示真实流程进度，刻度前沿按时间连续追赶（普通220ms、就绪120ms），不再限制每帧一根；连续相邻刻度可以在同一绘制帧点亮，不为动画延迟原图显影。
- 160 根点满后停留 80ms，再用 180ms 淡出及 3px 下移退场，只保留原有简短成片状态。减少动态效果直接更新并隐藏。
- 未到新目标时不排动画帧，完成/失败/卸载清除帧任务及计时器；没有持续扫描、呼吸或泛光循环。

## 进度含义

原图始终来自 NAS 成片路径，浏览器 fetch 使用 no-store。普通原图直接流式转发，读取 ReadableStream 累计接收字节，已知 Content-Length 时下载占 0–99%，浏览器解码成功占最后 1%。

HEIC/HIF/HDR 兼容路径先在服务端取回再转换。新增受馆主鉴权保护的 original-progress 查询，随机请求标识与照片 ID/revision 共同定位本次请求，300ms 一次且无并发堆积。它只存内存计数、不含路径或凭据，最多 64 项、10 分钟有效期；无后台清理定时器、不写 SQLite 或缓存目录。目前正式单 API 进程支持此机制，多 API 进程部署须共享进度或使用会话粘性。

兼容流程采用明确阶段权重：NAS 实际字节 0–90%、转换时停留 90%、转换文件传给浏览器 90–99%、成功解码后 100%。这是流程完成度，不是剩余时间预测；字节标签对应当前传输阶段，因此转入浏览器接收时总量会变成兼容文件大小。无长度时仅显示已收字节，不伪造百分比；收到完整响应后再推进至解码阶段。

切图/返回取消浏览器流、轮询、计时器与 Blob 引用；失败停住、保留 4K 并提供原有重试按钮。兼容转换仍沿用临时目录和响应清理，不常驻原图；这次没有重做服务端同步转换的断开中断机制。新进度接口本身不读取 NAS。

## 复验入口

构建到 data/original-progress/web-dist。设置 MUSEUM_WEB_DIST 为其绝对路径、MUSEUM_FIXTURE_PORT=8798、PYTHONPATH=.，启动 tools/p5_validation_server.py；必须等待 synthetic ready 后再运行。fixture 准备可能超过一分钟，不把端口尚未监听当作产品故障。

使用独立浏览器上下文执行 `MUSEUM_BROWSER_BASE=http://127.0.0.1:8798 node web/tests/original-progress.mjs`；其数据和截图写 data/original-progress。运行 `node --test web/tests/original-transfer.test.mjs`。完成后停止自己的 fixture、保留正式服务。正式静态包先复制 hash 资源再原子替换 index，后端进度接口随服务发布，保留既有会话和队列。

## 进度追赶修订（2026-10-26）

旧版每帧只亮一根导致160根在60Hz下至少2.67秒、30Hz下至少5.33秒，即使原图早已解码；还额外停留350ms。改用rAF时间戳插值，连续推进前沿。百分比与真实阶段绑定，视觉过渡不伪装成未完成下载。保留未知长度不报百分比、失败冻结、卸载取消以及完成后无常驻循环。

本轮隔离合成测试7组通过，增加瞬间完整下载/解码的突发路径和完成耗时断言。普通块跳变实测就绪到点满125.9ms、退出407.0ms；瞬间下载实测130.2ms、退出413.2ms。时间为本机Chrome自动化样本，后台页节流或主线程阻塞仍可能延后绘制，不能视为所有设备保证。测试断言前沿单调连续，不再要求每次DOM变化只增加一根。原图展示逻辑未加入等待。

证据：`data/progress-catchup/evidence/{browser,timing,burst}.json`。前端构建及diff检查通过，仅发布静态资源，正式API/worker保持运行。复验可设置 `MUSEUM_BROWSER_OUTPUT` 避免覆盖历史输出。
