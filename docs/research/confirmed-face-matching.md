# 已确认面孔的多样本匹配与是/否确认

2026-10-26。此前每个人物仅从SQLite分组中取一个任意样本，使用余弦相似度大于0.55进行在线归类。合并后新照片可以沿用目标人物ID，但多个已确认角度没有充分参与比较，也没有记录人工否认。

## 当前行为

已命名人物的人工确认面孔构成本地参考库。同一识别模型下，每人每张照片最多一个样本，上限12个；先保留较大面孔，再以特征方向的差异选择不同样本。新照片比较多个参考样本，充分匹配时自动归入已有姓名。自动结果仍标为自动，不自行升级为新的确认样本，防止误判递归放大。

算法版本`confirmed-multi-v1`独立记录，不升级视觉模型版本，不重跑全库识别。名下样本来源于馆主命名、合并、单面孔纠正或是/否页面的「是」。命名只保护当前有效面孔，不使失效模型自动结果重新生效。

默认自动归类条件：最高相似度至少0.65，至少两个不同照片样本相似度达到0.55；与其他人物的最高匹配相差至少0.10。如果只有一个参考样本，则要求至少0.80。对与已否认样本接近的照片要求额外间隔。多人同框不自动分给同一人物，同一照片已有该人物的人工面孔时，其他面孔不作为其自动候选。未达到条件时仍保留匿名分组。

这些数值是保守的产品启发式，尚未以馆主标注集校准；不能解释为身份正确率。OpenCV官方SFace示例同样采用[余弦相似度阈值](https://docs.opencv.org/4.13.0/d0/dd4/tutorial_dnn_face.html)，其中示例阈值对应其测试条件，不直接当本私人图库的质量保证。继续使用现有本地权重与许可证，不新增模型下载。

## Settings → 面孔与姓名 → 面孔确认

逐张显示待确认的照片上下文、面孔裁片、候选姓名及最多3张参考头像。显示「匹配相似度0.xx」，并注明不是身份正确率。

- **是，归入此人**：只移动这一张面孔，保留人工修订，并即时成为参考样本。不会将整个未核对分组一并合并。
- **不是**：记住这张面孔与该人物ID的否认，刷新后也不再重复同一问题；拒绝样本同时约束相近新照片的自动归类。
- **暂时跳过**：只在本次打开页面时略过，不写身份结论。
- **最近确认记录**：可以撤销。后续命名、合并或单面孔修订会保护相应的人工决定，旧撤销不得覆盖它。

候选从既有本地特征产生，要求相似度至少0.40；按250条分块检查，当前块无匹配时继续后续块，不能把第一块无结果当作全库无结果。每个块内按相似度优先显示，尚未做全库统一排序。面孔确认同时服务已有分裂分组；不会自动重新分配整座历史图库。

确认写入使用事务、版本/当前归属/目标姓名更新时间校验和请求ID幂等。失败保留问题；重新读取不会重复发送写操作。人工输入姓名仍不会因重名自动合并。

## 边界

只使用当前可见、当前文件revision、相同模型版本的特征，隐藏/越界/missing均排除。不同模型的向量不混用；旧模型人工身份依然保留，但需要同模型的确认面孔才能参加新匹配。姓名、照片、GPS、特征向量均不发送到云端；API不返回embedding。头像仅裁已有thumb，不GET NAS，不新增常驻原图或头像缓存。

新`face_reviews`保存是/否、原归属、算法/模型版本与撤销状态；`face_matches`记录新照片自动匹配依据。重做自动面孔时清理其旧匹配记录。识别模型本身没有被这些点击重新训练；提升来自馆主确认的多样本参考与负例约束。

否认绑定面孔ID与人物ID。改用新模型、重新生成了面孔ID或后来合并成另一身份ID后，可能需要重新确认；不以旧模型相似度否认新模型结果。

## 验证入口

后端`tests/p1/test_face_review.py`覆盖新照片归入姓名、多个角度优于单样本、自动结果不自训、是/否/撤销、近似负例约束、模型/范围/同框隔离、幂等与迟到答案、跨越无匹配分页。

UI使用`MUSEUM_VALIDATION_PEOPLE=1 MUSEUM_VALIDATION_FACE_REVIEW=1`启动隔离P5 fixture，运行`node web/tests/face-review.mjs`；只含生成风景与合成向量，不代表人脸识别准确率。再次运行需恢复临时fixture。既有`people-settings.mjs`继续验证命名和拆组。

真实索引只读副本快照：2个已命名且有当前模型确认样本的人物，共24个选用参考；热运行构建约95.7ms。对5,246个未确认面孔排名约0.11秒，生成2,221个候选问题。这是建议覆盖量，不是正确匹配数量；真实是否同人由馆主验收，未替馆主提交答案。细节仅在忽略的`data/face-review`。
