# Photo Museum 产品复审与下一轮建议

2026-10-27；源码基线 `ffb6b05`。本次为产品、代码与验证记录的只读复审，另查看了正式 Gallery 与 Dashboard。未重新运行全量测试、准确率评估、性能采样或付费策展；不将历史验证数当成本次验证结果。以下是待讨论的迭代建议，不修改已有产品约定。

## 当前产品判断

主链路已成立：只读 WebDAV → 持久任务 → 本地索引/双预览 → 活动浏览 → 原图细看 → 本地理解 → 自然语言策展。正式 Dashboard 本次显示完整处理文件 20,137、目录 228/228、待处理 0；这是当前规则下的流程完成，不表示所有照片都有人脸/GPS/确定标签，也不表示识别准确率通过。

展示层已有四款 Cover Flow，以及日历、地图、器材馆、时空隧道、人生年轮、记忆星图、记忆长卷、故地重游。活动照片墙与单图暗房是共用下钻路径。个人整理已有照片标记、人物命名/合并/确认与撤销、长卷章节编辑、故地重游配对；不能把这些重新列成从零开发。

下一轮建议命名 **P7：检索质量与个人策展**。重点是让已有照片更容易找到、选出的结果更可信、馆主整理成果更容易保存和恢复。先收敛这些流程，再增加新的展厅形式。

## P7.1：统一检索与结果质量

当前证据：

- 主体识别固定保留 MobileNet/ImageNet 前五个分类候选，未按低可信度拒绝；策展投影只保留类别/名称，丢弃候选分数。一个较弱的车辆候选也可能成为“有车”的命中条件。见 `photo_museum/providers.py:41–47`、`photo_museum/curator_tools.py:215–221`。
- 自由 query 是既有文字字段的包含匹配；不是理解图像的语义搜索。见 `curator_tools.py:287–292`。
- 地点是从 GeoNames 城市点中取最近点，国家、省份也来自该点，区/街道为空。不能把拼音翻译当作行政归属补全。见 `photo_museum/geography.py:23–35`。GeoNames 官方也分别提供邻近地名和行政区查询，两者不是同一口径：[官方说明](https://www.geonames.org/export/reverse-geocoding.html)。
- Settings 与策展的人物有效性条件存在差异：设置页排除旧自动模型，策展人物 SQL 未采用相同模型条件。此为源码发现，尚未在真实人物库复现影响。见 `intelligence_api.py:34`、`curator_tools.py:233–237`。
- Gallery 没有统一的复合条件检索入口，标记筛选主要在器材馆。简单查询仍容易落入完整 agent 流程。

建议交付：

1. 一个共享检索入口，按时间、地点、已确认人物、主体、器材、标记组合筛选，词库给有效词条提示；普通检索和 agent 使用同一有效数据投影。
2. 明确显示筛选条件和每张照片的命中依据。区分实测信息、模型候选和人工修正；支持“相关/不相关”反馈与撤销，不覆盖原模型事实。
3. 维护“汽车”等常用概念的可见子类范围，需展开时显示具体选中类别，不偷偷放宽主题、地点或时间。
4. 行政地点与“最近城市”分层保存，标准 ID、别名与人工修正独立；未知仍保持未知。
5. 策展先显示简短、可编辑的筛选计划。简单筛选走确定性检索，复杂分析再使用多轮 agent；为 schema/overview 增加有版本的复用，降低无关全库读取和重复提示上下文。

验收：先建立 20–30 条真实常用查询及 100–200 张馆主判断样本，记录 Top10 相关比例、漏检、无结果解释、首次结果耗时、工具调用数和 tokens。模型分数不视为正确概率；确定阈值或更换模型前做留出样本验证。同条件在普通搜索、agent、词库和展厅得到同一集合，人工修正可增量生效及撤销。

## P7.2：可修订、可保存的个人展览

当前策展 UI 已保存运行与展览结果，但结果区只有预览、展厅选择和 Show，缺逐张移除/补选、调序及改标题。已有长卷编辑围绕活动章节，不能替代任意跨活动照片集合。见 `web/src/curator.jsx:71`、`web/src/rooms/memory-scroll.jsx`。

建议增加“我的标记/我的展览”统一入口：任意展厅多选加入集合；agent 草案可直接修订；更换展示形式保留同一集合和人工排序；个人注释与事件记忆单独存储，不要求回写 NAS。普通删选和调序无需再次付费调用模型。

验收：跨活动选择一组照片，改标题、删选、调序、保存，重启后仍可打开；隐藏或源版本改变时明确标注失效项；人工修改有撤销和冲突保护。使用同一集合切换不同展厅，不悄悄扩大范围。

## P7.3：代表性精选与个人偏好

当前 Cover Flow 是有效美学分严格 Top10，本活动尚未补齐时整组回退技术分；没有近重复抑制或场景覆盖约束。agent 的 diverse 主要在不同活动间轮流取片，并非同一活动内按画面相似度去重。见 `photo_museum/gallery.py:277–289`、`curator_tools.py:346–354`。

建议在保留现有默认规则的前提下，先实验一个可选的“活动代表性”模式：识别连拍/近似画面候选，再兼顾不同时间段与场景；允许馆主固定或替换照片，保存独立选择理由。近似检测只用于建议，不删除任何 NAS 文件。是否改变默认封面策略，需馆主比较后决定。

个人审美层放在此后：已有神经美学和 A/B 试验，不应再把固定美学模型当作个人审美。先积累“漂亮、纪念意义、适合封面”三个不同维度的反馈，使用未参加训练的样本盲测；经馆主确认改善后再启用个人重排，保留一键回退。

验收：比较严格 Top10 与代表性精选的近重复占比、场景覆盖和馆主偏好；不能用总体分数下降自动判定代表性变差，也不能声称个人模型尚未验证的收益。

## 后续实验：本地语义搜索与日常回忆

本地语义搜索适合查“雨后街道”“夕阳中的背影”等未进入固定词表的视觉描述，以及以图找相似照片。已有 CLIP 用于固定 style/topic，但其向量尚未形成通用检索索引；可从本地 display 补建独立版本索引，零 NAS GET。OpenCLIP 的图文编码与相似度计算支持这条技术路线，但不证明现有权重适合中文检索：[官方实现](https://github.com/mlfoundations/open_clip)。先验证中文/多语模型、许可、空间、查询延迟和上述相关性样本，再决定模型；无需先迁移 SQLite 或引入独立向量数据库。

日常回忆可复用已存在的展厅：往年今日、继续上次、随机一场、已保存展览自动放映。高级屏保仍是原路线图的未完成范围；不必为了放映再造一种渲染体系。年度无月目录不伪造纪念日；自动播放只预热本地预览，暂停/隐藏时停止动画与无用预热。

## 与功能迭代并行的质量工作

- **备份恢复产品化。** 已有 SQLite 在线全库备份、密钥备份、去会话、校验及新目录恢复；下一步是 Settings 入口、最近成功时间、保留策略与恢复向导，并用后来新增的人名合并/撤销、面孔确认、人工集合/长卷做恢复演练。不能说现有产品完全没有备份。见 `photo_museum/backup.py`、`tests/p1/test_delivery.py`。
- **固定真实体验基线。** Chrome/Safari 与真实手机分开验收；固定大活动和高分辨率照片，记录首图、交互反馈、长帧、内存高水位、反复往返及后台恢复。历史已优化轮询/SQLite/worker，仍不能由合成零重绘推断硬件 GPU 休眠。阈值由同设备基线决定，不承诺任意机器恒定 60 fps。
- **数据质量处理入口。** 现有“需处理”与全局重试继续保留，增加按原因/阶段/目录定向处理；无 GPS、模型不确定、缓存缺失与真正失败分开。本次待处理为 0，不为演示而制造任务。
- **可移植版本。** 基础 Docker 只装媒体依赖，完整本地 AI、Mac 原生 HDR 与 Linux 编解码能力必须分别说明和验收。近期若不迁移，可排在检索和恢复之后。
- **整理当前版本文档。** STATUS/PRODUCT/运行说明存在历史规则与最新规则混排；将当前能力、限制、源码/静态包/schema/model 版本集中成短清单，历史追加内容留 changelog。版本信息用来定位实际运行内容，不冒充发布验证。

## 建议执行顺序

先做检索质量样本、统一有效数据与简单筛选入口；同时补备份恢复覆盖。随后完成个人展览编辑，再实验代表性封面。语义搜索采用独立试验页对照，个人审美正式学习等待真实反馈。新的展厅、HDR 全平台扩展及完整 AI 容器按实际使用需求排期。

本轮仅新增此复审文档；正式服务、任务、人物归属、评分规则与图库均未修改。
