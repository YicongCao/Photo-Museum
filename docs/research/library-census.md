盘点日期：2026-10-24（Asia/Shanghai）。这是候选文件名清单与小样本编码实验，不是已完成的全库 EXIF 刮削。私密逐文件证据只在被 Git 忽略的 `data/`。

- **227 个活动目录，19,536 个图片候选。** 其中 226 个活动在排除规则后仍有文件记录；空活动也计入目录总数。

- 两档图片缓存按17张成功 SDR 小样本外推 **8.52 GB**；加20%约 **10.23 GB**。采用每图两档合计1.5MB再加20%的保守规划场景约 **35.16 GB**。
- 当前图片规模远未显示需要200GB缓存或SQLite按年拆表。视频原件/转码、本地模型和临时文件需要单独预算，不能据此承诺整个服务只占10GB。

扫描状态 `complete`；成功列举 239 个目录（包含根目录、活动及嵌套目录）；失败 0 个。原始UTC时间为 `2026-10-24T10:34:22.593617+00:00` 至 `2026-10-24T10:38:59.068437+00:00`，约4分36秒；计数分类修订在读取同一份清单后进行，无需再次读取媒体内容。

这是不读取每张图片字节、避免逐媒体stat的文件名盘点。已知媒体后缀先计候选，正式入库仍需验证普通文件类型、解码、成片规则、内容哈希与EXIF。`.photo`等未知格式的专项核验见媒体报告；不通过改后缀猜测它们是成片。

扫描不是原子快照。恢复操作继续既有目录队列，不重新扫描已经完成的目录；要发现期间新增文件，开启新的盘点run。生产增量适配器尚未实现。未执行去重，全年总结与原活动可能同时包含同一张照片。

890 个视频未形成唯一文件名配对，其中包括待复核歧义和真实独立视频，不能将其全部认定为独立视频。LRF代理/SRT字幕单独记录，不能与成片重复计数。

## 缓存方案与空间

实验定义：长边3840像素的WebP（质量78）＋长边640像素的WebP（质量72），保留比例、不放大，ICC转换到sRGB/SDR，剥离EXIF/GPS。20张图片中17张通过此路径，3张HDR/gain-map单列暂缓；视频样本2段，其中2段HDR暂缓。未把未经色调映射的帧算成功。样本按年份与格式挑选，**不是随机代表样本**，不能据此给出统计置信区间或全库HDR比例。

| 场景 | 两档图片缓存 |
| --- | ---: |
| 17张SDR样本均值 × 全部图片候选 | 8.52 GB |
| 上述估计 ＋20%余量 | 10.23 GB |
| 假设每张1.5MB，两档合计，再＋20% | 35.16 GB |

这些值均不含视频原件/转码、SQLite/向量、模型、地图数据库。以640封面每个100KB粗略预算，全部视频封面额外约 0.21 GB；这是显式假设，HDR视频封面尚未实测成功。

建议先设 **80GB缓存硬上限**：照片衍生图、按需原生文件、视频转码和临时下载都在同一预算下预留/淘汰。缩略图优先保留；4K可LRU重建；原始视频按需读取，不提前全量复制。索引、人工精选和人物标签不随缓存淘汰。模型与数据库另行显示占用，未来增加离线地图数据前重新核算。

不要用文件数量直接推断NAS原始字节总量；本轮没有全量文件大小统计。首次全库转码时间也无法仅按0.9秒/张相乘承诺，NAS吞吐、HDR比例、CPU并发与解码峰值内存尚需正式管线测试。
