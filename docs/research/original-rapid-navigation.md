# 连续翻页与原图取消

2026-10-27。兼容原图原先使用单个转换名额，响应头返回前在同步处理函数中下载并解码；浏览器取消 fetch 不会通知该函数，下一张直接收到503。

自动读取现在等待进入转场结束及静止400ms，连续切换的中间照片不启动原图请求；点按“加载原图”不额外等待。翻页开始便中止现有fetch、轮询和解码，已加载的4K仍可见。

兼容原图端在响应头之前监听ASGI断开事件，将取消传给本地下载循环。转换在独立子进程组中进行，取消时结束整个进程组并清理工作目录、释放名额；新请求在有界时间内等待，不因旧请求正在收尾立即报忙。客户端接收期间仍由响应清理器释放。HTTPX底层正在等待网络字节或PROPFIND时，取消需要等该调用返回或网络超时，无法保证瞬间终止；普通原图沿用既有流式断开清理，预检阶段同样受网络等待约束。

不写NAS、不常驻原图，转换进程启用180秒上限；解码失败保留4K。取消不会被上报为失败。多用户并发继续共享转换名额，不让一个浏览器取消别人的任务。

复验：`tests/p1/test_view_original.py` 验证真实HTTP响应头前断线、等待请求继续、取消下载、终止转换进程、清理与响应体断线；另运行HDR、预览策略及服务回归。`web/tests/original-rapid-turn.mjs` 使用合成图库和受控网络，核对首张请求中止、连续三次翻页仅最终照片开始原图读取并成功显示；`web/tests/viewer-filmstrip.mjs` 复验按需读取、左右键、浏览器返回及过渡。正式8790重启后，独立标签页连续查看三张真实HEIC，最终原图兼容显示成功；这只验证普通翻页，不能当作真实NAS高速连翻或网络中断压力测试。测试日志和私密截图放`data/`。
