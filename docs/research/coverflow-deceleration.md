# Cover Flow 减速停靠

2026-10-27。馆主要求取消滚动收尾的回弹，提前计算停靠，让最后一段减速直接结束在封面正中。

## 原因与实现

原逻辑为滚轮即时位移，最后一次输入后等待180ms，再使用浏览器 `scrollTo(smooth)` 移向最近整数位置。它没有真实弹簧模型，但尾部停顿、二次启动、向后拉回的组合会呈现回弹感。

现在使用 `web/src/cover-motion.js` 的独立控制器：

- 活跃输入保持连续跟手。连续两次减小的滚轮增量视为惯性尾段，通过近期速度及减速度估计剩余路程，提前选择整数停靠点；有明确方向时不选择身后的封面，预测最多增加两张封面的惯性路程。
- 接管尾段后，同向持续变小的操作系统惯性事件被消费，不重复叠加一份惯性。反向、更强同向输入或相隔140ms的新输入立即打断并重新计算。
- 没有可识别尾段的普通滚轮/突然抬指用64ms短兜底；移除原180ms等待和浏览器的二次平滑归位。轻微滚轮也会沿方向停靠下一封面；拖动长时间停住再松手仍就近归位。
- 设剩余距离为d、初速为v，拟合 `a=v²/(2d)`、`T=2d/v`，按 `x=x0+v*t-a*t²/2` 逐帧运动。时长限制120–380ms，极慢/过期速度用剩余距离拟合初速，以免收尾拖长；这不是对操作系统物理参数的精确测量。终点速度为0，最后位置精确写成整数，没有过冲或弹簧。
- 拖动期间不自行漂移，松手用近期指针速度；按键、时间线、骰子定位共用无过冲停靠。四款Cover Flow共用，独立时空隧道的纵深运动逻辑不变。
- 减少动态效果直接到同一目标。页面隐藏时结束到目标；进入照片流/单图、卸载和新输入清理定时器/动画帧/指针捕获。静止时控制器不保持刷新。
- 逻辑位置使用“封面”单位，像素由当前stride换算；不改变封面数量、布局、缓存或NAS读取策略。

WheelEvent没有跨浏览器通用的触控板手指/系统惯性阶段标记，因此尾段识别采用有界启发式。真实触控板、鼠标与浏览器事件节奏不同，实际手感仍可继续微调。

## 本轮验证

- `node --test web/tests/cover-motion.test.mjs web/tests/cover-layout.test.mjs web/tests/random-cover.test.mjs`：19项通过，其中7项新检查验证单调轨迹、终速0、OS尾段只消费一次、短滚轮不向后拉回、新输入打断、拖动/取消/隐藏/减少动态效果、首尾范围及静止零待执行任务。
- Vite production build：236模块通过，未新增依赖或改锁文件。
- 隔离P5合成图库，IAB实际滚动采样：正向1.834→2，反向1.166→1，各有连续中间位置且没有反向样本；最终构建再次采样3.834→4，没有回拉。中央封面最终为 `rotateY(0deg)`。
- 按键2→3连续递增；按键运动中反向滚轮立即改向并落在2，旧目标未重新抢回。鼠标拖动落到整数2；390×844窄屏拖动2.714→3单调落位。照片流返回保留活动位置；纵向滚轮映射4.469→5且末端不越界。页面无捕获到的控制台错误。
- 交互通过CUA执行，数字轨迹在忽略的 `data/cover-stop-validation/interaction.json` / `final-trace.json`。合成截图见[停靠后](../design/previews/cover-stop/settled.png)。这是功能/轨迹检查，不宣称物理触控板或FPS基准。
- 旧 `web/tests/coverflow-settle.mjs` 已更新为新方向规则和可配置fixture入口，并通过语法检查；本轮没有从终端执行该浏览器驱动脚本，其交互证据以上述CUA检查为准。

## 发布与复验

正式8790仅发布新hash资源，再原子替换index，不重启supervisor或worker。使用馆主现有会话复核横滚与精确落位；真实截图只放data。

复验先跑上述Node测试；用隔离P5 fixture和新静态包检查连续输入、尾段打断、拖动、减少动态效果、边界、resize及照片流返回。不能再沿用“轻微正向滚动最后回到身后封面”的旧测试断言；可见轨迹应单调到目标，完成后无常驻动画任务。

正式复核：8790已加载最终构建main-CIVJ3MZA.js；真实图库146.416→147单调停靠，随后方向键恢复原活动146。后台supervisor及任务未重启。补修运动中打开活动时将停靠目标固定为所点封面，切到照片流后完成到该整数位置，避免返回半斜封面；最终合成构建进入/返回4.000、rotateY(0deg)、无控制台错误。
