## 词库应如何组织

使用本地SQLite中的派生表，不需要向量数据库，也不需要LLM参与建库。

1. **词条**：主体以已知taxonomy＋synset为主键，topic/style以现有词表ID为主键；城市优先GeoNames ID，保留国家/省份父级、原文/中文、最近城市精度。缺ID时使用带父区域的临时实体，不能仅按城市名字合并。本次271个城市都有稳定ID，但设计不能依赖永远如此。
2. **别名**：中文、英文、公开词表同义词、历史ID形式，各有来源和版本。NFKC、大小写、首尾/重复空格只用于检索规范化，原文保留。一个别名允许指向多个词条，不能给别名字串加全局唯一约束来掩盖歧义。
3. **照片关联**：记录asset/revision、词条ID、来源域及分析版本/媒体版本，计数按不同照片去重。机器候选保持候选身份；摄影主题不是活动目录主题，也不是“主体一定存在”的证明。
4. **关系**：另存同义/上位/相关关系及来源。上位概念“汽车”可以连接跑车、赛车、敞篷车等，但不能把所有含“车”的46个现有主体标签都自动当汽车；也不能把交通topic里的火车、自行车一并偷加进去。初期采用可审核的本地映射，相关词只用于建议。
5. **代际与更新队列**：首次全量构建成功后发布generation；此后以asset为单位删除旧关联、写入新关联并更新计数。标签变更、GPS/人工信息更改、隐藏/恢复、源revision变化都要入同事务的持久dirty队列；不是只监听新增照片。模型/词表/地理偏好整体升级时重建新代，成功后原子切换，保留上代直到新代可用。

全局词库与每次筛选后的候选词库使用同一套词条，查询时可加年份、国家、省份、活动等上下文，并返回条件内照片数。例如地点先确定后，再给agent看该地点实际可用的主体，而不只给它全库热门标签。仍应在最终准备时复验隐藏、版本和双缓存，词条计数不能代替最终可展示数量。

## 如何给agent使用

保留`list_facets`以兼容现有流程，补齐分页与分层信息；建议新增一个受限`lookup_keywords`工具作为自然语言选词入口。以下是拟议接口，并非当前已上线工具：

```text
lookup_keywords(query, domains, context, cursor, limit)
→ 标准ID、显示名、匹配别名、来源域、父区域、照片数、歧义候选、generation、next_cursor
```

排序先考虑精确别名、前缀、包含匹配，再考虑审核过的相关关系和上下文数量。稀有但精确匹配的城市不能被热门城市挤掉。普通名称、精确别名和上位概念要分别标注；拼音不能随意反推成汉字。

`search_photos`增加标准词条/城市ID筛选，由本地解析器编译成现有检索条件，模型不用拼原始数据库字符串。跨主体和topic的“任一域命中”必须显式表达，不能把目前字段间AND偷偷改成OR。“以车为主体”默认要求主体证据；“汽车题材”才适合允许topic辅助。自动展开仅限已经确定的同一实体别名，扩大范围的关系必须在返回的检索计划中说明。

`library_overview`只提供词库规模、版本、覆盖和查询方法，不把完整词库塞进系统提示。本次不含照片ID的词库清单已约292KB；逐轮全量注入会挤占上下文，并不必要地外发整个旅行地点列表。工具按需返回相关10–20条即可。

理想流程为“读字段/概况 → 按需查词 → 按标准ID检索 → 核对候选 → 创建草案”，减少换中文/拼音/英文反复盲试；实际能减少多少模型轮次仍需后续端到端A/B验证。

## 效果与资源实测

使用`tools/probe_keyword_lexicon.py`，SQLite以URI `mode=ro`及`query_only`读取；共享同一只读事务抽取当前投影。进程禁用网络，实测网络尝试0，不读NAS/原图、不加载图像模型、不访问真实provider。只向独立data目录写报告及原型。

- **确定别名恢复**：得到3,540个无歧义主体别名测试候选，其中1,576个目前无法直接用于精确筛选。专门从这些缺失别名中取20个，现有精确检索0/20非空，别名映射到同类别的已有ID后20/20非空，并与相应类别已有照片集合完全相同。这是词典回归样本，刻意测试缺失别名；**不是随机用户查询成功率、LLM提升100%或图像识别准确率**。
- **实际缺口举例**：`sports car`没有主体facet，但可以映射到已有标准主体类别；“汽车”没有主体facet、却有相关摄影topic；“车”会找到46种主体显示标签，仍需区分汽车和其他带轮物体。跨域词库和明确的概念关系比只去重字符串更有价值。
- **不能补出的地点**：“惠州”与`huizhou`在当前有效city分类中都没有记录，原型也不伪造命中。最近镇/城市不等于地级市行政归属；以后若要按完整惠州市范围检索，需要可靠的行政区层级/边界补全，作为独立地理增强处理，不能用活动标题或全省照片替代。
- **建库成本**：现有策展投影取数约4.2秒，隔离SQLite词库/关联原型约0.8秒构建，127,656条照片-词条关联，占25,387,008字节，约25.4MB。正式表增加出处、版本和dirty日志后会更大，预计仍是几十MB量级，须实现后复测；不增加照片缓存。
- **查询成本**：200次热缓存精确别名查询，中位数0.0066ms、P95 0.0077ms，SQLite完整性检查通过。这只测本地SQL，不含HTTP、鉴权、模型或整个策展查询；现有完整照片快照仍需约4秒，不能宣称端到端策展已经变成毫秒。
- **质量边界**：词库提高命名一致性、可发现性与精确类目的可检索性，不会修正主体模型误识别、补未运行的topic或缺GPS。相似度仍非正确率；没有标签不证明照片不含该主体。

## 建议实施顺序与验收

第一步交付确定去重/别名、分页查询、标准ID解析及独立增量索引；Settings提供词条、歧义、数量和更新时间的管理视图，尚不自动合并上位概念。第二步加入可审核的“汽车”等概念关系、地点父级和条件内共现数；不改原EXIF或模型原始结果。行政区归属补全单列，不以词库上线冒充完成。

验收应覆盖30–50条人工确认意图的中文/英文/别名/同名城市/空结果/组合查询；检查建议词前5项覆盖、解析后的照片集合、错误扩大范围、过期/隐藏记录撤出、增量幂等及失败后恢复。错误自动扩大范围、原图GET和不必要模型重跑应为0。随后用同一合成词库与请求集比较真实provider的工具次数、轮次上限失败、token和最终条件保持；私密图库只能本地验证，识别准确率仍需人工看图。

**建议优先做第一步。** 当前已有的数据量足以获益，收益主要来自修正身份重复、补别名与消除前60条截断；不需要先引入另一个agent来“二次理解”全库照片。
