# Gallery 返回层级、加载标记与照片流动效

2026-10-25。用户要求统一加载标识、浏览器返回、双侧封面、照片流入退场、横向控制及单图档案。本轮沿用React/DOM/CSS与本地thumb/display策略。

## 已实现

- 透明细线三联照片框Logo，SVG母版及640px RGBA PNG落仓；三片框沿折线依次收拢/展开，周期2.4秒。初始图库、展厅、选片、照片流分页、单图读取均复用该控件。减少动态效果时静止。见[品牌预览](../design/brand/loading-preview.html)。
- 使用History API记录展厅→照片流→单图→浏览器内铺满的层级；页面返回和原生Back共用记录。Forward、刷新恢复、活动/墙位置和当前集合范围一同校验。入口层可正常离开网站，不设无限返回陷阱。照片ID/revision在本机history.state中，不追加到地址栏；不保存原图/Blob URL。未知或范围外照片不会因历史恢复而进入展览。
- Cover Flow使用中心＋左右相同数量的真实活动封面，首尾循环选取并保持唯一；可见数采用奇数，正常图库最多19张以保留中间主封面（仍在此前5–20上限内）。左右同时预留时间线空间，四款样式均以中轴对称组织；纵深样式也随本次对称要求调整，覆盖先前偏左构图。方向按钮可循环切换首尾活动。
- Cover Flow进入照片流时：侧封面向左右退开，主封面缩小远离；照片流按横向位置依次用磁贴折转、位移和渐显展开。返回按相反方向接回封面；单图回到照片流亦有独立退场/入场。铺满与档案之间使用尺寸/位置过渡。快速原生返回会打断旧动画/请求，过期结果不覆盖新位置。
- 预热只等待集合元数据，不再等待15张4K全部取回后才开始入场。照片流先绘制缩略图，再请求/解码并渐换display图；缩略图优先级高、display优先级低，背景4K预热并发最多4个。未挂载瓦片不会请求原图。
- 底栏中央新增横向位置控制，鼠标、触屏和键盘可快速移动照片流；真实scrollLeft与百分比同步，返回保留位置，手机布局避让展签。连续滚动的历史同步合并为最多每500ms一次，进入下一层前立即保存，避免浏览器History API调用限流；待同步位置不跨历史条目写回。
- 删除档案中的“相机记录”，保留已修订/近邻推断等事实来源标签；所有档案项目配同色线条SVG。尺寸仅宽×高，增加源文件字节大小（缺失显示未记录），不额外取NAS。原图解码就绪后以暗房显影从4K过渡，最后恢复准确源色彩；错误保留4K，切图/退出取消并撤销临时URL。
- 时空隧道拼贴缝隙改为固定黄褐底色，距离减亮仅作用于照片；底部位置控制独立置于反射之上并核对实际命中区域。

- 既有P5四展厅26项通过，P6策展11项通过（合成provider，未调用付费LLM）；六种展示继续限定同一策展集合。
- 目录/媒体/服务24项后台回归通过，manifest体积等于已索引源文件大小。布局/拼贴专项13项通过，新增首尾封面数量及唯一性；resize专项6项通过。
- 正式服务已更新并以真实图库复验：HEIC原文件兼容显示、文件体积、铺满→档案→照片流→原活动的原生后退均正常；实际命中检查左右各5层封面可见。源配置指纹与schema不变，完成事件数量继续增长；没有新增扫描批次。
- 公共截图仅合成图库。透明PNG以alpha通道验证；真实照片截图仅保存至忽略的data目录。软件测试不代替真实设备HDR验收。

## 传输边界

本机直连进程仍为HTTP/1.1，未把并发图片请求称为HTTP/2升级。当前加载改进来自缩略图优先、非阻塞预热、请求优先级、虚拟化和本地缓存；前端也可运行于提供HTTP/2的部署后方。本轮未更改NAS、媒体版本、缓存预算或识别队列策略。
