# Dashboard 状态与待处理复审

## 状态问题与修改

旧“读取中”只表示React的media状态尚为null，不表示全库处理完毕。现场复核时页面已显示任务进行中，NAS刮削仍在继续；随后刷新真实页面复现媒体进度迟迟未返回：最近成功照片查询对cache_files做两次相关全表扫描，是已证实的加载瓶颈。

已增加迁移007，为cache_files(asset_id,revision,profile)建立覆盖索引。真实库同一查询修复前超过8秒被诊断超时中止，修复后0.296秒返回20条；查询计划已由SCAN变为SEARCH。迁移只增加索引，保留所有缓存记录和文件。

原实现把媒体进度与目录列表放在同一个Promise.all后更新，任一请求慢或失败都会阻止另一块数据展示。现在独立提交两块响应，每轮15秒超时、卸载取消请求；首屏“加载进度中”，首屏失败“进度加载失败”，后续失败“进度更新失败”并保留上次计数和更新时间，自动轮询和手动重新加载均可恢复。正常刷新保留实际任务状态，避免每2.5秒跳回加载。

任务状态区分媒体暂停、运行、等待、异常、全部完成和暂无任务。仅已有数据且全部文件完成、没有异常时显示“全部处理完成”。目录未加载时分子分母显示破折号。右上仅Settings、Dashboard、Gallery、锁定；照片源放Settings，手机当前照片按钮移至任务工具栏。登录按钮改为解锁，不再沿用馆务室名称。

## 异常分类与建议

1. **926张PQ/HLG HEIC（约30.58 GiB源文件）**：当前still路径仍明确拒绝这类传递函数，现有视频HDR转换不等于照片HDR已覆盖。优先实现受控的高位深解码、线性化、色域转换、tone mapping和sRGB输出；先抽取设备/编码代表样本验证高光、肤色、暗部，再只重试这一类。不要直接把HDR当8位sRGB保存。
2. **42张增益图HEIC＋9张其他HDR标记照片**：先确认SDR基底及ICC/NCLX，再决定复用有效基底还是转换；v2已有部分Apple/JPEG基底路径，不能因此假定这些失败样本都可用。分类型复验后针对重试，保留原始HDR事实和转换版本。
3. **52张缺少色域标记（51 HEIC、1 AVIF）**：优先读取容器色彩信息和导出软件/设备信息；仍不明确时提供人工确认的sRGB/P3策略并标为假定，不能把猜测写成实测ICC。相邻照片的色域不能直接代替逐文件事实。
4. **4个超过2 GiB的视频（1 MP4、3 WEBM，总约9.64 GiB，最大2.81 GiB）**：当前同名规则将其列为Live候选，先核实是否误配。确认非Live应使用既定只索引策略；确认属于需要播放的视频后再设计有上限的流式/Range解析或单独视频策略，不全局放大下载上限。
5. **1张超大尺寸JPEG（压缩文件约299 MiB）**：触发像素安全阈值。先只读尺寸，采用缩减解码/分块处理，在受限子进程生成4K与缩略图；不要关闭全局像素保护，也不要直接交给主进程全尺寸解码。

推荐顺序：让正常队列继续→先处理926张主类HDR→增益图/其他HDR→缺色域→4段大视频和1张超大图。每类修复经过小样本验证后定向重试；现在的“重试未完成文件”会重排所有失败/待适配项，在转换策略未变时只会重复下载和失败，不建议盲目点击。
