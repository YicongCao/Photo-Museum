# photo-museum：全屏人生照片馆

状态：2026-10-24 根据用户新要求修订的体验规范；尚未实现新 WebGL 原型或正式服务。

用户已确认：观展界面采用 Three.js／WebGL，在一块完整画布中呈现 A–F 六种模式；点击缩略图先快速显示 4K，再取回 NAS 原路径的原始成片，以数码暗房冲印动画完成升级。缺失 GPS／EXIF 可通过同目录文件名近邻推断并入库。第一版仍先完成可靠刮削、缓存和主题展览；本地识别、单馆主密码、先准确 SDR 后原生 HDR 均沿用。

## 产品主张与视觉

photo-museum 应让人愿意再看一次自己的生活。活动是展览，照片是展品，人物、地点和设备是重新理解经历的线索。展览层可以重新组织同一批照片，但不移动 NAS 上的文件。

进入观展后，整块视口就是展厅：没有网站式页头、页脚、长页面滚动或一排持续占位的导航栏。模式、筛选和退出入口以低干扰 HUD 出现，静置时收起，鼠标移动、触摸或键盘操作时可重新唤出。照片仍可直接操作，不依赖“发现隐藏手势”才能继续。

暖白纸感与 Swiss 排版保留为场景中的背景、标题、日期和展览编号；沉浸看图转为中性暗色。纸感与光影不叠到照片像素上，不改变用户作品的颜色。字体、对齐、比例和信息密度保持克制，游戏感来自完整视野、连续空间和流畅反馈，不需要人物行走、任务系统或复杂操控。

[concepts.html](concepts.html) 是此前的 DOM／SVG 色彩与排版研究，保留作历史参考。它的网页骨架、CSS 隧道和照片网格不再作为正式展示架构，也不能证明新版全画布体验已经验收。后续应制作独立的 WebGL 风险原型，再使用真实小样确认画面。

## 一块画布与共同交互

A–F 共用一个持久 Three.js renderer、画布、资源调度器和媒体查看状态。切换模式更换场景组织、相机与导航规则，不重建六套播放器或六个 WebGL 上下文。当前照片、活动、筛选、时间锚点和收藏状态跨模式保留。实现边界见 [观展运行时](../architecture/viewer-runtime.md)。

- **场景内容**：照片面片、展板、时间线、日历、地图、器材线稿以及主要可见 HUD 都在同一画布内绘制。照片墙使用纹理裁切坐标，日历使用画布图元，隧道使用场景深度和相机运动；不再按 DOM 卡片或 CSS 3D 方案实现普通观展路径。
- **命中与操作**：共用 raycast／命中区域与选择模型。可见按钮配有足够大的触摸区域；拖动与点击区分，滚轮、双指和键盘输入交给当前模式，避免一次手势同时翻活动、平移图像和缩放地图。
- **文字**：场景文字采用字形图集／可选 SDF 方案；中文按实际需要装入并限制图集页数，不为整个图库一次生成全部标签。可见文字与语义标签使用相同内容源，避免视觉日期与朗读日期不一致。
- **React 的职责**：登录、设置、刮削管理和必要的语义／表单层；观展场景内保持可访问的焦点与操作名称。必要的 DOM 语义镜像不形成第二套可见相册，不承担常规照片渲染。
- **全屏**：进入观展即铺满可用浏览器视口；“入馆／全屏”操作可请求浏览器真全屏。未获支持或用户退出浏览器全屏时仍保持完整视口的展厅，不承诺程序能随时隐藏浏览器界面。
- **可达性**：键盘可进入模式、选择照片、翻页、打开信息和退出；关闭大图恢复此前选择与焦点。减少动态效果时保留同样布局和操作，取消飞行、冲印位移等运动。无 WebGL 或上下文恢复失败时给出可理解状态及明确的简化访问选项，不悄悄把 DOM 相册当作主方案已完成。

游戏式连续画面不意味着整库常驻。只维持当前视野与少量前后候选，缩略图、4K、原图解码结果和 GPU 纹理各有预算；退出场景释放无引用资源。原始文件下载完成与可安全显示是两个状态，大像素原图需要受控分辨率或细节瓦片，不能直接把整库原图上传显存。

## 照片从缩略图到原图

这里的“原图”指已经被认定为成片的 NAS 原始文件，不是被排除的 ARW／DNG 等未处理原片。

1. **浏览**：各模式使用缩略图；选中后保持这一帧，立即优先请求本地 4K 缓存。4K 未缓存时使用已有缩略图直到更高质量就绪，不出现白屏。
2. **快速看图**：4K 一旦解码并准备好纹理就显示，可立即缩放、拖动、收藏或翻页。完整构图、方向、主体锚点和当前缩放位置在后续升级中保持稳定。
3. **取回原始成片**：服务端按资产对应的原路径与版本，从 NAS 读取当前照片；浏览器使用鉴权媒体接口，不能拿到 WebDAV 密码。默认只为当前打开的照片升级，旁边照片最多预取较小预览，不因翻开活动就下载全部原件。
4. **准备最终画面**：检测到浏览器／画布不能正确解码或显示的格式时，服务端提供准确标识的兼容版本。完整原始资源已取得、显示用纹理／瓦片就绪、原生 HDR 已验证是不同事实，不能合并为一个“高清已完成”。
5. **完成过渡**：当前照片的正确版本真正可显示后，再从 4K 切换到原图画面或可见细节瓦片。原图已缓存或很快就绪时直接／短暂过渡，不故意延迟观看。

画质状态保持简短且可展开：“4K 预览”“正在取回原始成片”“原图”“原图兼容显示”。当只准备了部分高分辨率细节瓦片时，不把整幅称为全分辨率已就绪。用户可以继续看 4K 或取消升级。原始文件比预览尺寸小也不放大冒充更多细节。

切到下一张时，旧请求与动画失去展示资格；即使旧照片稍后下载完成，也不能覆盖当前画面。按需取消与请求复用由调度器负责。断网、超时、解码失败或显存不足时保留可用 4K，结束等待效果，显示可重试的状态；不能让冲印动画无限循环。

## 数码暗房冲印动画

动画表达“这张照片正在被重新显影”，其基础是始终可观看的 4K。等待时可在画面边缘使用轻微相纸／光线提示与简短状态；不把已经清晰的预览重新模糊、漂白或遮黑。时间较长时提示收敛为安静的等待状态，不连续播放强烈视觉效果。

高质量画面就绪后，使用短暂的显影遮罩或细节浮现，将两档纹理对齐过渡。照片本身的色彩与曝光在最终帧回到正确值；动画材质和后处理退出，不给所有原图永久附加“暗房滤镜”。过渡时长、遮罩方向与幅度需通过新概念原型确认，不提前锁成昂贵的多级全屏特效。

进度来自真实可用信息：已知字节长度时可显示传输进度，未知长度时只显示阶段；下载完成后仍可能有解码／转换等待。不能用固定动画进度伪造百分比。减少动态效果或性能不足时使用简短淡入或直接切换，画质升级顺序和错误反馈保持一致。

## 六种展示方式

### A 时空隧道

活动作为沿深度轴排列的展板，当前活动展示最多十张代表作，远处展板使用更小的预览与降低的细节层级。相机沿时间前后推进，右侧画布时间线按年、月、活动定位；年度主题保留年份精度。

只实例化当前与邻近活动，距离足够远的活动用轻量占位。照片点击命中后进入共用大图查看状态，返回时恢复原展板位置。滚轮、方向键和触摸均有一致的推进规则，另有显式前后入口。移动端缩小纵深与同时显示数量，减少动态效果时相机即时定位，不靠连续飞行才能使用。

### B 纵向主题、横向胶卷

首版主模式使用正交或弱透视相机：纵向是活动，横向是同主题照片。活动标题、日期与胶卷一起在画布内排布；聚焦活动时让标题保持可读，避免只剩图像却丢失记忆线索。

共享输入系统将纵向导航与横向胶卷拖动锁定为明确手势；提供可见方向提示和“全部 N 张”。按视口虚拟化活动，胶卷只加载可见与下一小段缩略图。进入主题详情仍在同一画布内改变布局，精选是标记，不永久隐藏其他照片。此模式不依赖浏览器页面滚动或 DOM scroll-snap。

### C 可缩放日历

年、月、周是同一日历场景的三个细节层级。正交相机缩放／重排格子，年层显示月份代表图和密度，月层显示每日封面与数量，周层展开小胶卷；日期锚点在尺度切换时保留。文字、格线、照片和选择框共用画布命中模型。

只有日期精度达到“日”的有效值进入某天。推断日期范围以范围表达或“日期待整理”入口显示，不把未知日硬放到每月一日。同一天的不同活动可以并列。键盘方向导航、聚焦朗读和日期检索通过语义层支持，不要求用户只能缩放找图。

### D 地图与 Swiss 地点索引

在同一 renderer 内由地理适配器供给地图瓦片／几何，画布绘制底图、聚类、照片点与 Swiss 地名索引。国家→省州→城市→活动逐级进入；无需建立独立地图 canvas 或第二套相机交互系统。底图来源、授权、署名、离线策略和坐标转换由适配层明确，不把任何在线地图当作无限制的纹理源。

首次显示活动聚类，深入后才展开照片点；视口、缩放级别和筛选共同决定请求。底图缩放不悄悄改变用户已保存的筛选。无底图时可在同一画布使用地点层级排布，仍能进入活动。

地点标签使用有效值，同时保留“原始定位／推断地点／人工标记”的可查看说明。推断地点按其精度显示范围或近似提示，不在街道级制造精确点。不同国家行政层级允许缺项；坐标系转换不得覆盖原始 GPS。

### E 器材馆

相机与镜头以统一线条语法的轮廓构成画布展架／时间轴。线条几何或图集与照片面片由同一 renderer 绘制；点击设备后，相机聚焦其精选作品，展开首次／最近使用、常用镜头和典型焦段。真实型号轮廓需人工审核，不将猜测造型冒充准确产品图。

保留“这台相机陪我去过哪里”“同一焦段的十年”等个人叙事。机身与镜头是独立筛选维度；无法可靠区分同型号物理机身时按型号组织。只有从本张文件或可信同资产证据取得的器材信息才进入确认设备统计；近邻猜测不能把另一台相机的作品算到它名下。

### F 满屏照片墙与放映

根据画布宽高计算近方形单元，用 instanced 面片／批量绘制铺满整个视口，照片裁切通过 UV 和焦点坐标完成，不拉伸像素。模式 HUD 浮在画布上并可收起，不占一条固定网页顶栏。点击任一格进入完整构图，退出后保持墙的位置与播放进度。

共享筛选支持随机、从老到新、从新到老和分组渐进。随机使用可恢复 seed 与游标；换图只更新一部分格子并控制预取，避免全墙闪动和同时上传大量纹理。用户可指定裁切焦点；本地主体建议只作为可修订默认。

同一放映引擎还可提供双页相册、胶片长卷、单幅静观、同景跨年对照和往年今日。它们复用资源调度、筛选、播放顺序和暂停状态。默认无声，自动位移可关闭；减少动态效果时保留手动切换。

## 媒体、元数据与策展

大图查看是所有场景共用的画布状态，不是跳出展厅的网页弹窗。完整构图、缩放、拖动、上一张／下一张、收藏、信息与返回保持一致。原生 HDR 是后续专项验收，浏览器支持原生图片或视频不能推出它进入 WebGL 纹理后同样保留 HDR；没有验证前仍准确显示 SDR，不能悄悄换成另一套 DOM 观展路径并称全画布目标完成。

Live Photo 作为一个逻辑展品，画布中有可见标识与点击／按住播放入口；键盘可触发。视频解码器可以作为纹理来源，画面仍呈现在同一场景。普通视频单列、显示时长与中帧封面，点击再加载。兼容转码中保留封面，声音由用户开启；HDR视频与媒体纹理的颜色验证纳入后续验收。

缺失 metadata 的推断结果参与搜索、时间和地点组织，但必须能追溯。信息面板默认展示有效值，推断字段带简短标识；展开可见参考照片、方法和精度，并能修订或撤销。原始 EXIF、推断值与人工修订分层，曝光、尺寸、色域等不能从邻居照搬。具体供体选择、冲突和增量失效规则见 [元数据近邻推断](../architecture/metadata-inference.md)。

十张代表作仍以技术可用、去近重复、场景／人物／时段覆盖和用户选择综合产生，不能仅取审美分前十。推断日期与地点按置信和精度参与覆盖，不冒充真实定位。用户固定、替换、重排跨重新刮削保留；低技术分的纪念照片也可因用户收藏被选中。

## 登录与管理

登录、来源设置、刮削进度、错误复核和缓存管理使用清楚的 React 表单与列表。进入观展后收起管理信息，需要管理时显式退出／打开管理界面，不把后台表格铺在游戏式展厅里。登录仍只输入馆主密码，无用户名；NAS凭据与站点密码分开管理。

刮削阶段加入“缺失信息补全／待复核”，分别报告原始提取、推断成功、冲突和未知数。重新处理保留人工值；目录失败不解释为删除。缓存状态区分磁盘衍生图、临时原图／转码和前端可释放资源，不把4K编码文件小等同为显存占用小。

## 调整后的推进与验收

1. **P0.5 风险原型**：在正式展示页面前，用一块画布验证 B 模式骨架、共用大图、4K→原图冲印过渡、纹理预算、快速翻页取消与上下文恢复。使用占位图确认视觉，再用获准的小样验证媒体；旧 HTML 不能充当通过证据。
2. **P1 数据与服务契约**：除了可靠 WebDAV／SQLite，还提前定义版本化媒体 manifest、原图代理／兼容图／瓦片任务、每字段推断来源和依赖失效。避免等 UI 或本地 AI 完成后再重做索引。
3. **P2 首版闭环**：可靠扫描与近邻补全、缓存、全画布 B 主题展览、暗房大图升级、收藏与手动精选。以真实桌面和手机完成密码→入馆→看图→原图升级→返回→恢复任务的验收。
4. **后续展厅**：F 照片墙、C 日历、D 地图、E 器材和 A 隧道逐个成为共用引擎的场景；先验证少量活动再扩大。原生 HDR、部署和本地智能按总路线图分别验收。

关键用例包括：未缓存／缓存命中、NAS慢或断开、源文件版本变化、连续快速翻图、竖图升级方向与缩放锚点稳定、过大原图分块、HDR回退、无可用近邻、相机序列冲突、推断被真实EXIF替代、触摸方向锁定、键盘退出与焦点恢复、隐藏HUD可找回、减少动态效果、不同画布尺寸铺满和WebGL上下文丢失。

本轮只调整计划；全画布渲染、冲印动画与近邻推断均尚未实现。具体视觉原型、预算阈值和质量效果须通过新的验证，不能沿用旧DOM概念的验收结论。
