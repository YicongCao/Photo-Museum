# 缺失元数据的近邻补全

日期：2026-10-24。状态：根据用户新要求修订的实施方案，尚未实现、未对真实照片执行推断。本项属于 P1/P2 的基础入库能力，不依赖 LLM，也不等到本地人脸／审美模型阶段才加入。

## 目标与边界

同目录的成片缺少 GPS 或拍摄信息时，利用文件名序列和有可靠信息的近邻提出补全，并写入刮削库。展示和检索可以使用满足条件的补全结果，用户始终能分辨它是原始记录、推断还是人工修订。

补全只改变服务器索引，不向 NAS 写 EXIF、不改文件名、不改变照片字节。原始 EXIF 缺失仍然保留为缺失，不能把邻居的值写成“照片本来就有”。一个字段缺失不等于整个 EXIF 块应被另一张照片替换。

首先区分提取状态：`extracted`、`unsupported`、`read_failed`、`corrupt`。只有成功提取后确认缺失的字段进入自动补全；读取失败或不支持时先重试／修复提取器，不能用推断掩盖尚未读取的真实信息。格式能解码而 EXIF 不存在，是合法的 `extracted + missing` 情形。

## 数据模型先保留四层

采用逐字段事实记录及依赖关系，服务常用查询再维护可索引的有效值。表名可随正式 schema 统一，以下职责须在首次迁移时保留：

1. **原始值 `metadata_observations`**：资产／源对象版本、字段、原始值、规范化值、提取器版本、读取状态、数据精度。原始 EXIF JSON 是可追溯证据，不能被推断任务重写。
2. **推断值 `metadata_inferences`**：目标字段与目标版本、候选值或范围、方法及版本、配置哈希、供体资产和其原始记录版本、文件名序列组、证据摘要、置信等级、精度／不确定范围、状态和生成时间。
3. **人工值 `metadata_overrides`**：用户确认、修订、拒绝或明确清空，以及修改历史。明确清空是“保持未知”的决定，不能在下一次刮削又自动补上。
4. **有效值 `asset_metadata_effective`**：供筛选、地图、日历使用的物化结果。每个有效字段带 `origin` 和对应记录 ID，另有 `is_estimated`、`precision`、`uncertainty`。它是可重建索引，不是事实源。

解析优先级：**有效人工覆盖 → 本照片有效原始值 → 符合规则的已接受推断 → 未知**。人工清空也拥有最高优先级；异常原始值保留但不自动当成有效值。原始值与人工修订冲突时显示可查看的差异，不悄悄清除任一历史。

置信使用可解释等级，例如 `supported`、`tentative`、`conflicting`，不是未经校准的“93%正确”。位置范围是用于显示不确定性的保守范围，不包装为统计置信区间。API 返回来源等级，索引不能只留下一个没有来源的 `latitude` 或 `captured_at`。

## 哪些字段可以补，哪些必须独立读取

| 字段 | 补全策略 | 不允许的行为 |
| --- | --- | --- |
| GPS／活动内地点 | 从可靠供体得到候选位置或共同区域，保留供体与精度；满足规则后可成为“推断地点” | 把近邻坐标当精确拍摄点，或为凑地址伪造街道门牌 |
| 拍摄日期／时间 | 可靠文件名时间可形成“文件名推断”；近邻可给出时间区间、日期或相对顺序 | 把中点时间写成真实快门时刻，或从缺失月份伪造1月1日 |
| 机身／镜头型号 | 已确认同一拍摄资产的导出谱系可继承拍摄事实；普通序列最多给出待确认的设备候选 | 因 `DSC`／`IMG` 前缀相同就自动确认设备；用该候选填满器材馆 |
| 曝光、ISO、光圈、快门、焦距、白平衡 | 普通近邻不补；确有同一拍摄资产的证据时才可恢复该次拍摄事实并注明来源 | 相邻连拍也可能曝光／焦距不同，不能整块复制 EXIF |
| 像素尺寸、方向、编码、ICC/NCLX、HDR/gain map、视频时长 | 从当前文件或解码结果读取 | 从相邻照片继承，进而错误驱动转码、色彩处理或画面方向 |
| 人脸、主体、审美分、构图 | 由当前照片的本地分析任务产生 | 从相邻照片抄写人物、分数或分析结果 |

“同一资产的导出版本”与“同目录近邻”是两种不同证据。前者需要已确认的导出关联／可靠标识与复核依据；同名、相同编号或感知相似仅能发现候选。当前文件的尺寸、方向和色彩仍必须独立读取。补全任务不因此自动进入已排除的 RAW／原片目录搜索供体。

## 文件名与近邻选择

默认供体范围是**同一来源、同一实际父目录、同一活动、同一可比较序列组**。不能跨主题寻找名称最接近的照片；“全年总结”里不同活动复制来的文件尤其不能因为排序相邻而互相继承。

1. 保留原文件名，解析后生成附加字段：命名模式、前缀、数字序号、可识别的日期／时间、导出版本标记、解析规则版本。自然排序使 `IMG_9` 排在 `IMG_10` 前，但自然排序本身不证明拍摄顺序。
2. 依据稳定命名模式分组。已知机身、拍摄日期／时段不同是分组或冲突信号；设备未知时不凭前缀认定它们来自同一相机。只做明确规则支持的后缀归一化，不能随意删掉数字或将 `IMG_E1234`、`IMG_1234` 自动合并。
3. 检查号码重置、重复序号、跨日期、导出批次和排序与真实时间矛盾。号码从 `9999` 到 `0001` 不自动连接；改名为 `1.jpg`、`2.jpg` 的混合图库也不自动视为连续拍摄。
4. 优先查找已有证据确认的同一拍摄资产导出关系。没有该关系时，寻找序列内目标前后的最近**原始值可用**供体，记录原始数字间隔、真实时间间隔和空间差异。
5. 最大序号间隔、供体时间跨度、允许空间差异均是配置；初始值须在真实样本校准，并进入任务配置哈希。没有阈值的规则不得退化为“同目录任意远都可用”。配置与固定 fixture 必须使用显式值，避免测试依赖变化的默认常量。
6. 找不到可比序列、只有相同扩展名、文件名已随机化或证据矛盾时，保留未知或待确认建议。活动主题仍正常入库，补全失败不阻塞浏览。

不能使用读取返回顺序、文件 mtime 或压缩包排列顺序代替拍摄顺序。文件名中看似日期的数字也可能是导出时间；需要明确的命名规则和同批原始时间验证，解析成功不等于语义已确认。

## GPS 推断策略

**双侧供体一致是首选。** 例如 `DSC_4101` 与 `DSC_4103` 都有原生 GPS，序号连续、真实拍摄时间接近、地点属于小范围一致区域，而 `DSC_4102` 缺 GPS，则可生成 `supported` 的推断地点，供地图与地点筛选使用并标为近似。目标没有原始时间时，其时间证据是供体区间，不伪造一个精确时间参与后续判断。

默认采用某个真实供体位置作为候选中心，配合覆盖两侧供体差异的保守范围和来源说明，或只得到共同城市／区域。**不对经纬度简单平均，也不从两个端点线性插值制造拍摄轨迹**；路程可能绕行、跨海或经过其他城市，插值点可能落在根本没去过的位置。相同城市不等于同一街道。

只有单侧供体、数字间隔过大、供体缺少可比较时间、不同相机／日期混入时，默认 `tentative`，保存候选但不自动变成有效精确 GPS；用户确认后可使用。双侧供体地点相距较远或来自互相冲突的序列，标为 `conflicting`／保持未知，不选择更近的文件名强行填充。

数值有效性与业务可信度分开检查。纬度／经度范围、坐标系等不合法的原始记录不能作为供体；`0,0` 不仅凭数值就判定错误，异常位置需结合证据。GPS 精度、海拔和朝向不能从邻居一并复制；没有证据时单独保留为空。

供体只使用本照片的有效原始观察，或已确认同一拍摄资产的来源事实。**推断记录不能成为下一轮近邻的供体**，人工确认一条推断也不会自动将它升级为可传播的原生证据。这样可避免从一张误定位扩散出整场活动的假 GPS。

## 拍摄时间推断策略

- 文件名包含经过验证的拍摄时间模式时，记录 `filename_timestamp` 结果、解析模式与精度。没有时区就保存本地时间／未知偏移，不能默认套用服务器时区转成 UTC。
- 双侧原始拍摄时间可靠且同属连续序列时，缺失照片先记录 `capture_time_lower` 与 `capture_time_upper`，并按文件名序号保留相对顺序；不默认插值得到秒级快门时间。
- 两侧供体落在同一自然日，且时区语义一致时，可提供“推断为该日”的日级结果；跨午夜时保留跨日区间。日历不把跨日区间强行塞进任意一天。
- 只有一侧时间或目录仅提供年月时，保留对应精度或待确认建议。年度主题只提供年级回退；活动主题和 EXIF 事实分开索引。
- 排序使用“已知时间／推断范围＋稳定文件名顺序＋资产 ID”的明确规则；不能把排序辅助键回写成真实拍摄时间。筛选跨区间的照片时显示“时间约在此范围”，也允许仅筛选原始日期。

## 写入、失效与人工修正

一次推断任务的输入版本包含目标对象版本、供体原始记录版本、目录序列快照、规则版本和配置哈希。先在事务外计算，再在短事务提交前检查版本仍匹配；刮削期间供体已变更的结果不能覆盖新版本。

`inference_dependencies` 反向索引使下列变化只触发相关目标重算：

- 目标后来提取到原始 GPS／EXIF：已有推断标为 `superseded`，有效值优先使用真实记录；有效人工覆盖仍保留。
- 供体内容、EXIF 或手工修正发生变化：基于旧观察的推断标记陈旧，按供体资格重新计算，不把旧值一直当事实使用。
- 新文件插入原序列：重算受影响的邻域，原来的左右供体不再保证是最近邻；只处理该组，不重跑整个照片库。
- 源目录已成功完整核对并确认供体被删除／移走：使有关推断失效。NAS 断线、权限失败或扫描未完成，只标可用性，不推断删除或清空所有补全结果。
- 人工拒绝该字段推断：记录拒绝原因与规则／目标版本；同一证据不反复提出相同建议。新证据可以产生新建议，但不会自动覆盖人工清空或修订。

人工修正直接影响有效层，原生记录和被替代推断留作可追溯历史。任务失败不会抹掉上一次仍有效的值；被确认陈旧的推断不继续参加默认精确地点／日期筛选，界面显示“待重新核对”。

## 地址解析与展示

近邻推断是本地规则步骤，逆地理编码是另一个 provider。先确定可使用的坐标或地点精度，再按用户启用的地图／地址服务解析；不为了提高“补全率”把所有低置信候选发送到网络。

由推断坐标得到的地址继承其推断来源和不确定范围，不能因为 provider 返回完整门牌就升级为精确事实。区域只支持到城市时，国家／省州／城市可用于近似筛选，街道／门牌保持未知；服务返回字符串与实际可用层级分开保存。省州、城市、街道等字段允许为空。

API 与全屏观展信息层显示简单标识：“相机记录”“根据附近照片推断”“你已修订”。需要时展开供体、推断范围与修改入口；普通观展不展示原始JSON或算法参数。地图以近似点／区域表达不确定性；日历把跨日、跨月和未知日期内容放在对应的待归日分组。统计可按来源过滤，不能把推断 GPS 覆盖率写成原生 GPS 覆盖率。

## 实施位置与验收

**P1** 建立原始／推断／人工／有效值模型、字段提取状态、依赖失效与任务版本约束；媒体列表 API 一开始就返回来源和精度，不在后期用字符串标签修补。

**P2** 增加文件名规则解析、同目录序列分组、双侧 GPS／日期的基础补全、建议复核及筛选表现，与 EXIF 入库一起完成。流程为：提取目录已有成片事实 → 形成可用序列快照 → 推断缺失字段 → 有效值／展示索引 → 活动精选。地址provider未启用时跳过逆解析，联机地址解析按P4接入；P2无需依赖外部地址服务。增量后只重算有关邻域，推断不阻塞缩略图和4K加载。

固定测试至少覆盖下列可观察行为，使用合成文件名与元数据，不从 NAS 写测试文件：

| 用例 | 应有结果 |
| --- | --- |
| 同目录同组，两侧原生 GPS 相近且时间接近，中间缺失 | 写入带双供体版本的推断；原始 GPS 仍为空；有效层标近似 |
| 只有左侧 GPS／两侧相距很远 | 保存待确认建议／冲突，不能填有效精确坐标 |
| 两台相机混在同目录且序号相近 | 不跨可辨识设备序列借值；未知分组时保守处理 |
| `IMG_9999` 与 `IMG_0001`、重复编号、随机改名 | 不按简单数字最近邻跨重置连接；无法确认时未知 |
| 同名照片在相邻两个活动、年度总结复制文件 | 不跨真实父目录和活动边界传播 |
| 缺整块 EXIF 但文件能解码 | 可按规则补地点／时间；尺寸和颜色来自本文件；ISO等仍未知 |
| EXIF 提取网络失败 | 进入读取重试，不使用推断伪装为已完成读取 |
| 双侧时间跨午夜／时区未知 | 保留范围与偏移未知；不编造精确日／UTC时间 |
| 新增原生 GPS、供体被修改、序列插入新文件 | 对依赖定向失效／重算；人工覆盖不丢失 |
| 从已推断 B 再推断 C | B 不具备原始供体资格；禁止级联扩大补全 |
| 用户清空地点或拒绝建议后重新刮削 | 保留决定，不自动填回 |
| 目录读取中断／暂时离线 | 不当作供体删除；不清空整个目录的有效元数据 |
| 推断点逆解析返回街道门牌 | 按原始不确定范围限制展示层级，不伪造门牌精度 |

完成这些实现与行为验证后，再把流程加入项目 skill；本次仅修订设计，不把规则文档当成已经跑通的推断能力。
